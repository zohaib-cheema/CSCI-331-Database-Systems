What I built

A Python runner parses a SQL workload, executes it against MySQL, records duration and row counts in a metadata database, and generates a browsable HTML report. Assignment 14 compares several logically similar count queries before and after indexing query_assn.

View the audit trail

The raw report records counts of 1,153–1,156 before indexing and 1,159–1,162 afterward. That monotonic pattern is consistent with telemetry writes, not a change in query semantics. The right conclusion is to repair the experiment before claiming a speedup.

✓

The important finding

Benchmark design matters as much as query syntax.

How I would productionize it

Freeze a fixture dataset

Run every trial against the same versioned, read-only snapshot.

Separate telemetry writes

Log to another schema or buffer measurements until each trial ends.

Use EXPLAIN ANALYZE

Capture actual timing, row estimates, access type, and chosen keys.

Run repeated trials

Warm the cache, randomize order, and report median plus variance.

Monitor pipeline health

Validate stable row counts and alert on failures, drift, or missing plans.
